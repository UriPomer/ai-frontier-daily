## 本期摘要

本期最重要的信号不是“模型参数又增长”，而是四个方向正在合流：

1. **Agent 能自己维护运行环境，但自我修改必须有不可变的内核。** Exo 把 Harness 优化带进执行时；HarnessMM 则把重复推理替换为有证据约束的可复用决策。
2. **记忆要从“摘要文件”演进成“原始日志、索引、可检索知识表示、注入上下文”分层体系。** Anthropic 的 Dreaming 实验给出了数据，也揭示了错误记忆被持续传播的风险。
3. **研发加速与安全治理需要独立测量。** METR 报告所见 Anthropic 能力增长速度约为历史的 1.9 倍，但不确定性、披露删节和因果归因仍然重要。
4. **检索、验证与专用模型正从单一 LLM 调用里拆出。** DecisionRAG、独立 Critic、EmbeddingGemma 2 都为专用子系统提供了可测量的替代路径。

下列 11 项按**开发者可操作性 × 技术新意 × 证据质量**综合筛选，而非机械照搬新闻排序。

## 1. Exo：运行时自我修改 Harness，同时保护最小可信内核

**分类：** Agent Runtime / Harness / Self-improvement  
**周刊：** 11 月 7 日；**论文：** 2026-10-30 初稿，11 月初进入公开检索。  
**原始论文：** [Exo: An Architecture for Self-Improving Systems at Runtime](https://arxiv.org/abs/2611.00463)

**核心观点。** 传统 Harness 优化先离线生成候选、跑基准、挑版本，再部署；Exo 则让执行中的 Agent 修改自己的策略和 Harness 代码，在真实工作中学习。关键是将**可编辑策略层**和**不可被 Agent 任意修改的机制层**分离：后者保存执行历史、控制新策略激活与审计，前者以可检查的代码 diff 演进。

**技术原理。** 完成任务的轨迹既用于执行，也产生“应当如何改变下一次工具选择、Context 构建或工作流”的候选修订。修订不是直接获得最高权限，而是经过受保护机制层。与只更新 Prompt 的自演化方法相比，Exo 的变更范围包含可执行 Harness 逻辑。

**证据。** 作者报告：在开放世界游戏长任务中，单独运行相对 Codex/Pi 下降 **12%—53%** 模型成本；迁移运行下降 **45%—82%**；在 AppWorld 和 SREGym 的留出任务上，相对不可自修改版本下降 **35%—61%** 成本，正确性大体保持。属于作者所选环境和模型条件下的结果，不应直接推广到生产。

**为什么重要。** 它把“改进 Agent 的循环”从开发者的独立工作流，移到了 Agent 自身的 Runtime。但越是允许自修改，越需要隔离不可变安全边界，否则一次错误修订会累积为系统性风险。

**开发者启发。** 从有限的配置空间起步，例如让 Agent 提交规划深度、工具路由与重试策略的差分；每次记录 base version、diff、触发轨迹、成本与回归结果，经过测试后才激活。不要允许运行任务的同一 Agent 修改授权、审计与回滚逻辑。

## 2. Claude Dreaming：离线整理记忆，不只是给历史做摘要

**分类：** Agent Memory / Context Engineering  
**发布：** Anthropic，2026-11-06。  
**原始研究：** [The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)；[Dreams API（Beta）](https://platform.claude.com/docs/en/api/http/beta/dreams/create)

**核心观点。** Anthropic 将记忆拆为四层：可搜索的原始对话/执行日志、当场写下的记忆笔记、Wiki 等长期知识表示，以及每次会话预加载的少量关键 Context。Dreaming 是**会话间的离线整理计算**，能校验笔记、修正错误、整理索引、合并重复内容，并选择哪些信息应升至注入层。

**技术原理。** 原始 transcript 充当证据层，笔记和 Wiki 是派生视图；离线回放时 Agent 可根据原始记录纠错并重新组织链接。预加载层必须小：官方提及 Claude Code 仅加载 MEMORY.md 前 **200 行或 25 KB**，作为导航入口，而不是把所有历史塞回模型。

**证据。** Anthropic 对约 **35 万文件、4.2 亿 tokens** 的文档语料构建 25 题评估。随着 Dreaming 轮次增加，仅用 Wiki 的得分从 **13% 升至 48%**；**Wiki + 搜索**从 **54% 升至 61%**，相比纯搜索 **53%**，且每题约节省 2 万 tokens。其 Pokémon 导航案例还显示：离线核对 transcript 可以修正错误的地理记忆，从而避免重复失败。以上测试量有限，部分为定性案例。

**为什么重要。** 这比“每隔 N 轮总结聊天记录”更像数据库与知识管理：原始日志是事实来源，结构化记忆只是可重建的索引。记忆命中率之外，还应测量错误继承、过时信息与重建成本。

**开发者启发。** 为持久 Agent 设计四层存储与引用链：event log → notes → wiki/index → small startup context。离线整理应提供来源定位、差分、时间戳和撤销；所有可能影响关键决策的长期规则要能回溯至原始证据。**不要把 Dreaming 等同于模型权重更新。**

## 3. METR：Anthropic 的 AI 研发速度约达历史基线的 1.9 倍

**分类：** AI for AI R&D / Independent Evaluation / Governance  
**发布：** METR，2026-11-05。  
**原始报告：** [Independent Assessment of AI R&D Acceleration at Anthropic in October 2026](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/)；[对 Anthropic 风险报告相关部分的复核](https://metr.org/blog/2026-11-05-rd-section-anthropic-risk-report-august-2026-review/)

**核心观点。** METR 在 **2026-08-12 至 10-29** 期间对 Anthropic 做高访问权限评估。其主要判断是：截至 2026 年 10 月，Anthropic 在可明确定义任务上的能力改进速度，可能达到 2024-03 至 2025-10 历史速率的约 **2 倍**，而 AI 辅助研发可能贡献其中多数。

**技术与方法。** 核心不是统计“使用了多少次 Claude”，而是追踪 Anthropic 的 AECI 等能力指标、训练计算量、算法/工程效率、内部人员访谈及自报提效，尝试区分算力扩张、组织改善和 AI 工具产生的速度效应。

**证据与不确定性。** 公开 AECI 测量估计增长速度为历史的 **1.9 倍，95% 置信区间 1.5—2.8 倍**；METR 认为不能用训练算力扩张单独解释。与此同时，大量最能支持判断的内部证据受到 Anthropic 删节；METR 明确警告公众不能独立检查其中大部分关键材料。该报告**并不等于**“已经实现完全自主的 AI 研发闭环”。

**为什么重要。** Agent 开发不能用主观“感觉更快了”论证自动化：需要把能力成长、人成本、实验吞吐、模型进步和自主程度分开测。

**开发者启发。** 在研发团队记录 task lead time、实验吞吐、有效 PR、回归率、人工介入比例和每个成功交付的实际成本；分别报告“AI 辅助的人类生产率”和“无人工干预完成的任务占比”。

## 4. Weight-Space Programming：直接编辑模型权重修复推理循环，但不是通用的“无训练提智”

**分类：** Model Editing / Interpretability / Optimization  
**发布：** MIT CSAIL 研究者，2026-11-02（**研究博客，非同行评审论文**）。  
**原始研究与实验日志：** [Sparks of Weight-Space Programming](https://rikiyat.github.io/blog/weight-space-programming/)

**核心观点。** 研究者让 GPT-6 Astra 阅读网络结构、权重张量及有限测试反馈，再直接编写或改写权重；不执行反向传播或梯度下降。这种方法把“网络权重”视为可诊断、可局部修补的程序材料。

**技术原理。** 对 Qwen3.5-0.8B，Astra 在探索运行中定位到第 15、19 层 MLP 输出里与重复循环相关的方向，只修改 **131,072 个参数（约 0.016%）**。它并非完全零反馈：这组成功实验最多使用 **50 次前向测试**来辅助定位与验证，只是没有梯度训练。

**证据。** 在相同采样设置下，MATH-500 **7.9% → 48.1%**，GSM8K **13.8% → 67.1%**，IFEval **21.0% → 62.3%**；MATH-500 触及生成长度上限的比例 **93% → 33.1%**。但对原本很少陷入循环的 Gemma 3 270M，MATH-500 仅从 **6.8%** 最多升至 **7.7%**，不能证明它能创造原本不存在的推理能力。

**为什么重要。** 这为可解释性驱动的局部权重修复提供了极早期证据，但与“自动训练下一代大模型”是两个不同命题。大幅指标提升主要来自**解除可识别的生成故障**。

**开发者启发。** 先定位具体 failure mode，再考虑低秩干预、特定方向消除或少量层编辑；保持完整 checkpoint diff，并在目标任务、非目标任务、稳定性和安全性上做配对评估，避免只报告修复后的单项 benchmark。

## 5. GPT-6 Cyber：能力提升之外，更值得关注的是作用域约束和独立验证

**分类：** Security Agent / Model / Evaluation  
**官方发布：** OpenAI，2026-11-05；**周刊：** 11 月 7 日。  
**原始公告：** [GPT-6 Cyber: Advancing the frontier of aligned cybersecurity agents](https://openai.com/index/introducing-gpt-6-cyber/)

**核心观点。** 新专用网络安全模型强化了漏洞验证能力，并在授权研究场景中强调**明确作用域、避免越界目标和可审计验证**。这对所有具备高权限工具的 Agent 都具有结构性意义，不局限于安全测试。

**技术与证据。** 官方公布 ExploitGym **48.5%**，相对 GPT-5.6 Cyber **32.1%**；在单独的作用域约束基准里，无部署 Prompt 时避免越界的比例为 **99.93%**，加入部署 Prompt 后达到 **100%**（均为指定测试集成绩，不能推导出普遍绝对安全）。公司将模型列为其 Preparedness Framework 下网络安全 **Critical** 水平，限制高级能力访问。

**为什么重要。** Agent 能力越强，执行边界越不能只依赖自然语言。模型“知道不应该做什么”与系统“技术上不能越权”是两种不同保障。

**开发者启发。** 授权范围应成为工具执行层的强制白名单，敏感动作需要独立验证和详细日志；对高影响任务使用隔离环境、权限最小化与可回滚流程。上面的研究成果应视为防御性评估指标，而不是通用工具授权的理由。

## 6. DecisionRAG：利用不生成文本的决策模型在文档树中导航

**分类：** Retrieval / RAG / Decision Models  
**周刊：** 11 月 1 日；**原始论文：** 2026-10-26。  
**原始论文：** [Retriever-Free Retrieval: Navigating Documents with Decision Models](https://arxiv.org/abs/2610.35868)

**核心观点。** DecisionRAG 把第一阶段相似度检索换成树形文档导航：从主题到文档再到段落，每层用决策模型**同时比较多个候选分支**，只沿可能相关的分支向下走；不需要生成逐 token 的分类答案。

**技术原理。** 在平衡层级结构下，纵向决策深度随语料规模近似对数增长；在同一次上下文比较同层候选，能利用相对信息改善可比性。可以让 Jev 等决策模型提供快速的相关性打分，而不是 LLM 输出长篇推理和 JSON。

**证据。** 在无任务专用训练的设置下，相比“dense retriever + 8B reranker”，作者报告 MultiDoc2Dial 的 R@1 **+13.8 个百分点**、Natural Questions 的 Hit@1 **+17.4 个百分点**；包含 268 万维基段落的测试中，检索延迟 **0.7—1.8 秒/查询**。这些结果依赖文档层级质量和候选剪枝预算。

**为什么重要。** 它提出搜索不一定必须“先做 embedding 最近邻”，而可以是低成本模型主导的结构化浏览。不过早期剪错分支就无法恢复召回。

**开发者启发。** 对代码库、项目 Wiki、长文档先构造稳定目录树，比较“混合 BM25/向量召回 + reranker”和“层级决策导航”的 Recall@k、延迟与成本；必要时保留向量检索作为 fallback。此方向与此前报道的 Jev 是**应用延伸**，非对 Jev 的重复介绍。

## 7. HarnessMM：通过有守卫条件的决策复用消除重复模型调用

**分类：** Agent Cost / Harness / Tool Execution  
**周刊：** 11 月 1 日；**原始论文：** 2026-10-23。  
**原始论文：** [HarnessMM: Recursive Self-Improvement for Harness Token Efficiency](https://arxiv.org/abs/2610.32813)

**核心观点。** 工具完成后，Agent 常常再次让模型判断已经确定的后续操作。HarnessMM 将历史决策整理为 **Executable Decision Graph（可执行决策图）**，当当前工具回执满足公开的 Guard 条件时，直接复用确定的动作与字面参数，避免重新调用模型。

**技术原理。** 决策图显式记录动作、参数、因果依赖与 Guard；Guarded Decision Reuse 识别已确认的状态，Certified Callback Substitution 通过原生工具接口执行并计量省去的模型调用。对没有充分证据、出现新语义决策或选择器拒答的情况，**回退原 Actor**；外部 RSI 流程在验证集上选择有效配置。

**证据。** 作者在 HumanEval 相同 98 道任务上报告：DeepSeek Harness 的成功率 **71.43% → 85.71%**，tokens/task **96.28k → 11.62k（-87.93%）**；Codex 保持 **90.82%** 成功率，tokens/task **-29.54%**。收益与提供商缓存计费、重复动作比例和决策图维护成本有关。

**为什么重要。** 很多 Agent 延迟并不是“推理不够快”，而是“同一个决定不断重新做”。这种改进不必改变基础模型权重。

**开发者启发。** 先对调用日志按工具名、稳定参数和回执归一化统计重复率；只缓存满足**状态前置条件**的操作。涉及外部写入、支付、删除等非幂等动作时，必须重新检查授权和目标状态，不能机械重放。

## 8. Rethinking Verification：独立 Critic 的性价比往往高于结束时自我反省

**分类：** Agent Evaluation / Quality Gate / Coding  
**周刊：** 11 月 1 日；**原始论文：** 2026-10-25。  
**原始论文：** [Rethinking Verification in Agent Harnesses](https://arxiv.org/abs/2610.34577)

**核心观点。** 作者比较了 **17 种** Agent 检查策略，覆盖初始说明、执行中提醒、完成时门禁、外部独立审查；在多个编程模型与 Terminal-Bench、SWE-bench Verified 上验证“在哪里增加一次检查最值得”。

**技术原理。** 同一 Actor 自检常与其原始误判高度相关，独立 Critic 则能从输出工件、变更 diff 与任务约束出发重新给出证据。额外回合并不总是划算；检查点位置比“检查 Prompt 多长”更重要。

**证据。** 独立 Critic 在 Terminal-Bench 上平均改善 **5.9—9.5 个百分点**，成本约为基线 **1.13—1.25 倍**；在 SWE-bench 上改善 **3.9—6.6 点**，成本约 **1.00—1.04 倍**。完成时拒绝式门禁也能提升准确率，但成本最高达到约 **1.76 倍**。VisualBench 上审查最终变更往往比回顾完整轨迹更有价值。

**为什么重要。** 为“多给 Agent 一次思考”与“换一个审查角色”提供了可比较的经验依据。

**开发者启发。** 将第二个 Agent 的预算优先给验收而非重复实现：读测试结果、diff、运行截图和约束清单；只在 Critic 提供具体证据时重新打开任务。针对游戏编辑器、Web UI 等视觉产物，要让 Critic 看最终可见效果，不只看日志。

## 9. EMMA：把多 Agent 配置当成可归因、有限度更新的情景记忆

**分类：** Multi-Agent / Episodic Memory / Self-improvement  
**周刊：** 11 月 1 日；**原始论文：** 2026-10-25。  
**原始论文：** [EMMA: Structured Episodic Memory for Multi-Agent Workflow Synthesis](https://arxiv.org/abs/2610.35966)

**核心观点。** Agent 系统演进时，一次任务失败可能导致模型任意重写 Prompt、增加子 Agent 或修改技能库，变化难以归因。EMMA 为三层状态赋予明确所有权：Controller 的路由记忆、Specialist 的职责描述、Step Skill 的局部步骤知识。

**技术原理。** Reflector 分析执行失败，把改动归因到**最小负责范围**，只提交一处增量修改，并通过与具体 Backbone 无关的 Guard 限制改动大小与类型。这样能降低不同任务间的记忆干扰，也使 A/B 验证更直接。

**证据。** 在 KramaBench、AppWorld、BBEH 与五个模型骨干上，作者称 20 个设定中排名第一的有 **17 个**，对最强基线最高提升 **32.5%**，训练执行次数比最省基线还少 **17%—38%**。但失败任务中被采纳的无效编辑仍可能长期残留。

**为什么重要。** 自改进体系的竞争不仅是“能自动更新”，更是“更新范围是否可界定、可回滚”。

**开发者启发。** Skill、路由规则和全局指令要分层版本化；出现失败时优先定位责任层，记录最小 diff，配合跨任务回归；不要让一个局部工具失败触发整个 Agent 身份或全局策略重写。

## 10. EmbeddingGemma 2：轻量多模态统一向量，让本地 Agent 检索覆盖图像、音频与视频

**分类：** Embeddings / Multimodal / Edge AI  
**周刊：** 11 月 1 日；**原始论文：** 2026-10-27。  
**原始论文：** [EmbeddingGemma 2: Unified and Efficient Multimodal Representations](https://arxiv.org/abs/2610.37364)

**核心观点。** Google 把文本、图像、音频、视频与混合输入映射至统一向量空间，同时把模型拆成按需载入的模态组件。总参数约 **744M**，其中包含约 **167M 视觉编码器、305M 音频编码器、271M 双向 Transformer**。

**技术原理。** 文本模式只需 271M，视觉 + 文本约 439M，音频 + 文本约 577M；训练通过多阶段课程把文本学习、多模态学习、蒸馏和对比目标有序组合。支持 int4 量化、调整视觉 token 预算和缩短向量维度。

**证据。** 论文报告 MTEB Multilingual v2 **61.36**，MTEB Code 相比上一代 **68.76 → 78.68**；但 MTEB English v2 **69.67 → 68.46**，并非所有项目都提升。int4 在多语言测试中约损失 **0.4 点**。参数规模优势与部署收益仍要按真实硬件验证。

**为什么重要。** 长期 Agent 的知识源不是纯文本：截图、录屏、语音片段、场景图和代码文档都需要被统一检索。

**开发者启发。** 对多模态资产库可先用统一 embedding 做候选检索，再用专用模型复核；评估跨模态 Recall@k、索引体积、CPU/GPU 内存占用、量化影响和误召回，勿因统一空间而忽略模态特有细节。

## 11. Agentic Backdoors：预训练中极少量污染可能在工具调用时触发后门

**分类：** AI Security / Training Data / Supply Chain  
**周刊：** 11 月 1 日；**原始论文：** 2026-10 月下旬。  
**原始论文：** [Agentic Backdoors via Pretraining Poisoning](https://arxiv.org/abs/2610.37741)

**核心观点。** 一种无需在推理时显式 Prompt Injection 的风险，是恶意样本先进入预训练语料，随后模型在执行正常工具任务时因特定输入模式触发异常行为。该研究关注预训练污染能否穿过后续正常训练而保留，属于**研究环境下的安全风险演示**。

**技术与证据。** 研究者报告在 4B 模型的实验设定里，污染约 **0.1%** 的预训练语料后，特定输入触发的 Pass@32 攻击成功率达到 **92.7%**；清洁输入下观察到的触发率为 **0%**。这是特定触发器、采样次数、训练流程的结果，不能直接换算为真实系统被攻击的概率。

**为什么重要。** 仅做推理期 Prompt Injection 防护并不足以覆盖训练数据与模型来源问题；模型行为可能在后训练看起来正常，却在稀有输入上异常。

**开发者启发。** 强化训练数据来源记录、异常样本检测、模型供应链追溯、稀有触发模式的红队回归；对所有命令执行型 Agent 使用最小权限和隔离容器，即便模型来自看似可信的检查点。

**针对科研/模型编辑：** Weight-Space Programming 适合在小模型上作为可解释的故障修复实验；不要将“去除循环使模型能完成回答”误当成“凭空获得更强数学能力”。所有模型编辑都应保留原模型、同采样设置和多任务回归。

## 本周观察

**首先，性能比较开始从“哪个模型强”转为“模型 × Harness × 验证器的单位交付成本”。** GPT-6.2 Astra/Sol、Gemini 4 Neon、Qwen4-Max 和 Inkling 2 Mini 体现了不同的能力—成本取舍；FrontierHarness v1.1 直接证明，更换模型后最省钱的 Harness 可能完全换位。

**其次，长期 Agent 的经验管理正在分成三条可验证路径。** SoMem 允许模型自主组织带来源的文件记忆；WikiTrace 强制经验与原始轨迹互相链接；Meta Self-Improving Memory 则先搜索记忆读写策略，再将部分策略行为蒸馏进权重。它们与上期 RIME、Recursa、Routed CL 互补，但不是同一实现。

**最后，研究自动化的瓶颈正在转向可复现性、科学价值与审计。** 936 个研究 Agent 产出大量论文，不等于有同等规模的重大科学发现；形式化量子程序、ReproBridge、AutoRefine 提示：生成数量之外，应独立验证正确性、实验发生事实和长期评测质量。

## 一、模型与 Agent 产品更新（11 月 16—21 日）

### 1. GPT-6.2 Astra / Sol：从单次模型跑分走向交付成本与专业工作流

- **类型/日期：** 前沿模型、编码 Agent、计算机使用；2026-11-17。
- **原始来源：** [OpenAI 官方发布](https://openai.com/index/introducing-gpt-6-2-astra-sol/)；[官方 API 发布说明](https://help.openai.com/en/articles/9624314-model-release-notes)。
- **核心观点：** Astra 面向最难的专业/科学工作，Sol 用较低单位成本执行日常多步任务。OpenAI 报告 Astra 在 Agents' Last Exam 比 GPT-6 Astra 高 5.2 个百分点，同时每任务成本不足其三分之一；Sol 在 FrontierCode 2.0 与新 Astra 相差约 0.5 个百分点，却只有约五分之一的任务成本。
- **技术原理：** 公开信息侧重更高效的长轨迹规划、工具调用和更少输出 tokens，而不是提供可独立复现的全部底层训练细节。官方建议保持前缀稳定、把新指令追加到会话后部，从而改善 prompt cache 复用与连续任务推理。两个模型都可在 API 中调用。
- **关键限制：** 标准 API 每百万 token 价格：Astra 输入/缓存输入/输出 $8/$0.40/$40；Sol $2/$0.10/$10。论文/发布页中不同基准和对比模型可能采用不同思考档位，且两者在高风险安全能力上有额外防护。厂商的性价比宣称应在真实任务集上复测。
- **重要性与开发者启发：** 建立“Sol 默认处理—验证失败再升级 Astra”的路由基线，同时保留“全程 Astra”对照；记录完整工作流成功率、工具调用数、缓存命中、总费用和人工验收时间。对于包含可视化、3D 与复杂交互的工程任务，应保留可执行产物测试，而非只评估截图。

### 2. Gemini 4 Neon：高智能、低延迟与中途可纠偏性一起被优化

- **类型/日期：** 多模态模型 / 生产型 Agent；2026-11-18。
- **原始来源：** [Google 官方发布](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-neon/)。
- **核心观点：** Neon 被定位为复杂软件工程、知识工作和科学任务的高效执行模型。Google 报告其在 Artificial Analysis Intelligence Index 的 xhigh 档得分 61、总榜第 3；在 Agent Arena 的 steerability（任务中途接受纠正）维度排名第 2。
- **技术原理：** 不仅要求最终答案强，还强调长任务中可根据用户的新约束稳定调整计划；高价值 Agent 要把“中途纠偏、恢复、验收”视为第一等能力，而不能只测从头到尾一次完成的成功率。
- **证据与边界：** 发布时给出的 API 价格为每百万输入/缓存输入/输出 tokens $3/$0.15/$15，支持百万 token 上下文。排行榜与厂商内部错误率实验不能直接证明特定私有代码库的质量。
- **开发者启发：** 把临时变更需求、撤销错误操作、部分工具失效加入自动化任务集，对比 Neon 与上期 Hydrogen 的执行/编排分工；统计纠正后是否破坏既有成果、是否反复重读上下文及最终成本。

### 3. Inkling 2 Mini：循环 Transformer 用“内部重复计算”换取少输出 token 的推理

- **类型/日期：** 开放权重、小型 MoE、推理架构；2026-11-20。
- **原始来源：** [Thinking Machines Lab 技术发布](https://thinkingmachines.ai/news/inkling-2-mini/)；[官方模型卡](https://thinkingmachines.ai/model-card/inkling-2-mini/)。
- **核心观点：** 该模型总参数约 26.4B、单次激活约 3.4B，但部分中间层每 token 循环执行三次，使有效的权重激活计算约 5.4B；目标是在不生成冗长外显推理文本时增加内部计算。
- **技术原理：** Looped Transformer 对同一组中间层重复应用，形成与常规“增加层数/增加输出 token”不同的计算分配方式。大部分权重采用 NVFP4，最后四层采用 MXFP8；官方称权重占用约 20GB。另发布可变循环数研究变体，支持测量额外循环对推理能力与 CoT 可监测性的影响。
- **证据与边界：** 官方报告 DeepSWE v1.1 48.2%、Vals Index v2.2 46.5%，并展示循环数增加对某些任务帮助明显。不同模型的评测配置与理论解码吞吐无法简单等同实测本地速度；循环也可能减少可供审计的文字思路。
- **重要性与开发者启发：** 对本地编码 Agent，比较固定循环与可变循环的“耗时/成功率/峰值显存”，不要只用 tokens/s 衡量。对于需要审核的高权限行为，应以工具执行日志、文件差分和外部检查为准，而非相信可见思维链完整。

### 4. Qwen4-Max：大规模稀疏 MoE 与工作流推理成本协同优化

- **类型/日期：** 旗舰多模态模型；2026-11-16。
- **原始来源：** [阿里巴巴集团官方公告](https://www.alibabagroup.com/en-US/document-2060139246777270272)。
- **核心观点：** Qwen4-Max 采用 2.4T 总参数、每 token 激活约 71B 的稀疏 MoE，支持原生视觉与百万 token 上下文；阿里巴巴称它在 Work360 的 721 类专业任务中较 Qwen3.8-Max 使用少约 35% tokens，平均任务成本降低约 60%。
- **技术原理：** 官方提及对注意力、残差连接与嵌入层的 MoE 设计升级，并通过降低激活参数规模改善推理经济性；配合多工具工作流和云资源调度闭环。该公告没有完整公开训练配方、架构消融与第三方完整复现。
- **证据与边界：** 厂商报告 Code Arena 第 6 名；Work360 属于其自有评测，应特别避免与其他厂商不同设置的榜单作强结论。发布时可通过 QwenCloud 等服务访问；公告所称随后将发布的“小型开源权重版本”不代表 **Qwen4-Max 本体已经开放权重**。
- **重要性与开发者启发：** 比较中英双语复杂工具链、代码维护和长文档工作时，以最终“正确完成一个任务”的成本和重试率为核心。可以同时把工具结果裁剪、缓存策略与路由器固定，避免多变量评测归因混乱。

### 5. FrontierHarness Eval v1.1：同一 Harness 的成本名次会随模型大幅逆转

- **类型/日期：** Agent Harness 基准 / 系统评测；2026-11-17。
- **原始来源：** [Runta / Baseten 研究公告与方法](https://runta.com/blog/introducing-frontierharness-eval-v1-1/)；[项目](https://harness.runta.com/)。
- **核心观点：** 基准扩展到 **22 种 Harness × 5 个模型 × 62 个任务 × 4 次尝试**，共 27,280 次执行，约 830 亿 tokens。它揭示“最佳 Harness”不是独立于模型存在的常数。
- **技术原理：** 在统一任务与运行环境上观察通过率、每任务成本、缓存与运行时间，并为不同模型寻找成本—质量的 Pareto 组合。成本排行在换模型时明显变化：按每任务成本，Harness 名次移动中位数达 11/22；Codex CLI 在 GLM-5.3 为第 1，换 Kimi-K3 变第 16。
- **证据与边界：** 官方给出的最佳价值组合因模型不同而异，例如 GLM-5.3 对应 Codex CLI，GLM-5.3 Flash 对应 Pi，DeepSeek V4.1 Flash 对应 ZCode。基准覆盖固定工程任务和硬件设定，不能直接推断所有仓库和框架。
- **重要性与开发者启发：** 模型升级必须同步重测 Harness；建立 2×N 的配对实验，冻结环境、任务与预算，逐条追踪工具输出长度、上下文压缩、自动重试及缓存。不要依据单一公开榜单把某 Harness 永久设为默认。

### 6. Meta Self-Improving Memory：先自动寻找记忆策略，再把部分行为蒸馏入权重

- **类型/日期：** 长期记忆 / Harness 搜索 / LoRA 蒸馏；研究博客于本周公开讨论（作者公开介绍为 11 月 17 日）。
- **原始来源：** [Meta FAIR 原始研究博客](https://facebookresearch.github.io/RAM/blogs/self_improving_memory/)。
- **核心观点：** 与只依赖固定 Markdown 记忆提示不同，该方法让元 Agent 根据任务轨迹修订写入记忆的 **OFFLOAD** 与读出记忆的 **LOAD** 提示，并通过留出任务验证筛选；随后用优化提示产生轨迹，再把轨迹中的提示替换为通用提示进行监督微调。
- **技术原理：** 第一阶段是在 Harness 层搜索元策略；第二阶段使模型学习在通用记忆提示下产生较好的读写行为。元 Agent 与任务 Agent 均使用 Kimi-K2.6，训练并非完整参数重训，重点在把外部提示策略“内化”为模型行为。
- **证据与边界：** Continual Learning Bench 三项任务中，优化提示平均 **56.0**，最佳人工提示 **44.6**；蒸馏后通用提示场景为 **43.1**，用普通轨迹训练的对照为 **37.6**。**56.0 不等于蒸馏完成后的 43.1**，不可混报。搜索成本、基础模型依赖和任务泛化仍是限制。
- **重要性与开发者启发：** 即使不做 LoRA，也可先比较多个 LOAD/OFFLOAD 策略：仓库导航索引、错误日志、结构化经验、假设验证；每次选择应基于独立任务而不是最近一条漂亮示例。与上期 RIME 的 Actor/Writer 联合 RL 不同，这里重点是 Harness 搜索与蒸馏。

### 7. A Society of AI Scientists：936 个 Agent 证明可大规模协作，但产量不等于突破性研究

- **类型/日期：** 多 Agent 科学研究组织 / 元科学；alphaXiv 页面 2026-11-21 提交（相关公开报道在 11 月 19—21 日）。
- **原始来源：** [alphaXiv 原始论文与实验资料](https://www.alphaxiv.org/abs/2611.society-ai-scientists)。
- **核心观点：** 在 12 周、35 个人类运营的实验室里，936 个自主 Agent 产出 936 份研究及代码/数据，交换约 9,500 条消息并创建 229 个聊天室。社区逐渐出现主题小组、纠错、主动撤回与 Agent 审稿的行为。
- **技术原理：** 实验室人员提供计算资源、预算和大方向；Agent 在共享预印本与消息系统上提出假设、执行实验、审稿与引用其他 Agent 成果。核心不在增加单个模型上下文，而在建立可复用的研究社群协议和证据留存。
- **证据与边界：** 作者披露代码、数据、论文与交流记录。盲评观察显示 Agent 论文在实验严谨性等方面有优势，人类论文在新颖性/重要性上仍更强；盲评依赖 LLM 评审，结果是探索性研究，不代表独立人类专家已认可所有结论，也不能把 936 篇等同于 936 项可靠发现。
- **重要性与开发者启发：** 构建“假设—实验—原始数据—复核—撤回”可追溯链比单纯增加研究 Agent 数量更重要；多 Agent 工作台应允许负结果、互相引用和复现失败标记，避免无证据的自我强化引用。

### 8. Devin Bots：从“一次任务代理”转向长期拥有目标的工程协调代理

- **类型/日期：** 持续工作 Agent / 多代理协调；2026-11-17。
- **原始来源：** [Cognition 官方介绍](https://devin.ai/blog/introducing-devin-bots)；[产品页](https://devin.ai/bots)。
- **核心观点：** Devin Bot 保存跨会话记忆、调查待办、把目标分解为多个 Devin 子会话并行处理，持续验收和选择下一步；只有需要人类判断的事项进入“Needs You”工作队列。
- **技术原理：** 与单个 Coding Agent 执行一张工单不同，Bot 是持久的任务所有者和调度层：状态、子任务、工具授权、审批门槛与复盘都跨多个工作会话存在。它改变的主要是软件交付责任分配，而不是一个独立披露的新基础模型。
- **证据与边界：** Cognition 报告一个 Android Bot 在 44 天内合并约 1,134 个 PR，期间有约 183 条人工消息。这是企业自身案例，未提供与人工基线等价的独立质量审计；PR 数量、代码行数不能代替故障率、用户价值与长期维护成本。
- **重要性与开发者启发：** 长期工程 Bot 适合限定范围的依赖升级、回归测试和性能专项；从权限最小化、PR 验收规则、预算上限、回滚路径、共享记忆隔离开始部署，发布与敏感写入应有独立授权边界。

### 9. Eval Optimizer：对不同评测自动挑选“代码、判定模型或 Agent”作裁判

- **类型/日期：** Agent 评测基础设施 / Judge Router；2026-11-19。
- **原始来源：** [Judgment Labs 官方发布](https://www.judgmentlabs.ai/blogs/eval-optimizer)。
- **核心观点：** 用户以自然语言描述评分标准，由系统根据轨迹中证据所在位置、难度与范围，自动配置确定性代码、轻量决策模型、前沿 LLM 或带工具 Agent 作为裁判。
- **技术原理：** 先基于轨迹确定评分的证据范围与预处理方式，再选择足够可靠的判定计算，拿人工标签校准后规模化执行。人类仍负责定义正确的 rubric；自动路由负责减少不必要的高价模型判断。
- **证据与边界：** 官方称某客户任务中单次评测成本最多降低 **50 倍**，这是特定工作负载案例，不是跨所有评测的保证。路由系统本身仍可能带来漏报和分布漂移。
- **重要性与开发者启发：** 将验收分成可执行单元测试、证据检查、语义判断与人工审查，不要让一个大模型统管所有评分；先构建人审金标准样本和“误判代价”权重，再优化评测成本。这与上期 JevAct 的在线工具门禁不同，属于评测自动配置层。

## 二、本周新收录的重要论文（论文初稿早于筛选窗口，明确标注）

### 10. s³：从共享强化学习奖励中涌现多 Agent 协作规则

- **类型/时间：** 多智能体强化学习；arXiv 初稿 **2026-11-05**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.08615](https://arxiv.org/abs/2611.08615)。
- **核心观点：** 一个由同种模型副本构成的团队不预先设领导、角色或发言顺序，Agent 自主决定独立工作多久、何时发消息、何时查看同伴进度。
- **技术原理：** 对动作与通讯采用共享团队回报进行多 Agent RL；协作信息本身可以因为帮助队友成功而得到正向训练信号。论文观察到互补角色自发出现，且训练时较小规模的协作规则可推广到较大的团队。
- **证据与边界：** 作者报告将推理团队规模扩为训练时两倍后，在协调任务上的解题数量超过最强对照 **25 倍**，探索重复工作减少近 **50%**，相比 best-of-N 最高提高 **9.4 个百分点**。实验主要使用小型 Qwen3 模型及特定协调环境，不能直接断言大规模商用多 Agent 会获得相同倍数。
- **开发者启发：** 即便没有训练资源，也能对比“固定分工”“自由沟通”“不沟通并行”三种 Harness：统计通讯 token、重复检索、独立发现率、互相污染和总任务成功率；对于共享结论保留证据来源。

### 11. SoMem：让 Agent 自己组织带引用的普通文档记忆

- **类型/时间：** 长期记忆 / 可追溯文件知识库；arXiv 初稿 **2026-11-09**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.11929](https://arxiv.org/abs/2611.11929)；[代码](https://github.com/Qi202/SoMem)。
- **核心观点：** 记忆不必预设固定的 slot 或关系图 schema；Agent 可以创建、合并、修订主题文档，但每一条提炼后的结论仍关联不可编辑的原始互动证据。
- **技术原理：** 写入端由运行时校验编辑，再从文档生成时间线、关系和近期视图；读取端根据问题主动检索主题、沿链接追溯原始记录，不强迫所有查询只用向量相似度。
- **证据与边界：** 相对最强对照，作者报告 LoCoMo、BEAM-100K、LongMemEval-S 上分别高 **2.66、3.10、2.00 个百分点**。改写文档可能引入误归纳，跨用户/跨项目读权限必须由系统侧保证。
- **开发者启发：** 为所有记忆项加入 source_id、时间、置信度、过期规则；让 Agent 能返回“这条结论基于哪次实际执行”。与上期 RIME（训练记忆写入）不同，SoMem 更关注不用改模型权重的外部知识组织。

### 12. WikiTrace：用原始任务轨迹防止“错误记忆反而害人”

- **类型/时间：** Agent 记忆可靠性；arXiv 初稿 **2026-11-10**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.14320](https://arxiv.org/abs/2611.14320)。
- **核心观点：** 经验摘要可能错误，甚至让原本可解决的任务失败；缺少原始轨迹时，Agent 无法判断一句“经验教训”到底是否适用。
- **技术原理：** 存储为 **简短 insight → 成败诊断 → 原始 trajectory** 的证据链；新任务中发现经验冲突、细节缺失或来源于失败尝试时，Agent 通过工具沿链接回查并纠正。
- **证据与边界：** 周刊总结五个任务基准平均比无记忆高 **10.7 分**、比只给相同摘要高 **3.2 分**；“曾经能做却因记忆失败”的比例由 **6.5% 降至 4.5%**。这些收益受轨迹质量、检索策略与任务分布影响。
- **开发者启发：** Skill 和项目记忆不只保留“最佳实践”，也记录该实践来自哪次实验、当时什么版本及失败条件；使用之前先核对适用性。SoMem 管理文档，WikiTrace 重点在错误经验的证据校验，可组合使用。

### 13. Verified Quantum Programs：形式化证明把 AI 算法发现推到无法常规模拟的规模

- **类型/时间：** AI for Science / Lean 形式化验证；arXiv 初稿 **2026-11-06**，**11-16 修订到 v3**，11-15 周刊收录。
- **原始来源：** [arXiv:2611.09822（当前 v3）](https://arxiv.org/abs/2611.09822)。
- **核心观点：** Google DeepMind / Google Quantum AI 将量子程序的正确性和成本上界形式化为 Lean 目标，由 Gemini 4 Agent 团队搜索实现、生成证明，并交给可信内核检查。
- **技术原理：** 团队共享已验证解、部分进展及失败结论，在“可证明程序”空间搜索；数学证明承担正确性判定，而不是靠小规模量子电路模拟外推。这里的核心可信根是规格、证明内核和独立检查，并非 Agent 自信程度。
- **证据与边界：** **11 月 16 日 v3 的 arXiv 摘要**报告并行搜索最高 **2.57 倍**、量子算术 **290 倍**，若干科学模拟场景分别 **12/8/2.5 倍**。早期摘要及周刊所报约 1.4、2.55 与 11 倍存在版本差异；本报告以标明的 v3 为准。理论程序的加速不等于已有量子硬件上普遍达到同等加速。
- **开发者启发：** 对精确可判定的工程任务，分离“生成候选”和“独立验收”；先用类型约束、编译器、定理证明器或单元测试构建不可由模型自述绕过的评分信号。上期 AlphaProof Code 着眼已有代码的安全验证，本研究着眼可证明的新量子算法发现。

### 14. LongCapHarness：不训练底模，也能迭代其长上下文能力调用方法

- **类型/时间：** Training-free Harness / 长上下文；arXiv 初稿 **2026-11-07**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.10463](https://arxiv.org/abs/2611.10463)。
- **核心观点：** 对许多长文检索与推理任务，不一定先合成数据再微调；可以把能力拆成检索、判断、排序、跨段连接等更小原语，优化围绕冻结模型的流程。
- **技术原理：** 一个更强的 Harnessing Agent 在开发集上递归调整原语实现、状态和控制逻辑；完成后冻结可复用的 Harness 库。改进属于外部计算图和工具使用，而不是改变 Llama3-8B 的参数。
- **证据与边界：** 论文称在 HELMET / RULER 上优于若干数据合成与训练方案，估算开发成本不足部分训练对照的 50%；周刊另报告特定设置平均提升 64.18 分。**构建这些 Harness 使用了更强模型**，不能宣称整个流程不需要高能力模型或代价可以忽略。
- **开发者启发：** 先对长任务实施“证据定位 → 独立子题 → 可引用答案合成”的冻结工作流，再决定是否 LoRA；严格分开开发集与隐藏测试，防止 Harness 对特定格式过拟合。

### 15. Agency：Harness 费用有时主要花在“反复阅读旧上下文”

- **类型/时间：** Agent 系统优化 / 计算经济学；arXiv 初稿 **2026-11-09**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.12122](https://arxiv.org/abs/2611.12122)。
- **核心观点：** 在相同模型/任务下，Harness 的改变可能对成功率影响较小，却令成本差到 **2.6 倍**；优化不一定要换模型，先减少被反复读取的上下文和无效工具输出。
- **技术原理：** Agency 在现有 Harness 与模型调用之间做插入层，统一处理上下文、工具和环境优化；论文分析中，上下文重新读取最多占成本 73%，平均只有 27% 的工具输出最终被用到。
- **证据与边界：** 作者实现五类概念验证优化，报告在若干真实基准上节省最多 **35%** 成本而不损失准确率；具体改善与任务轨迹有关，不能预期每个 Agent 都有相同浪费。
- **开发者启发：** 从日志中分离“新生成 tokens、重复前缀读取、工具输出、失败重试”成本；限制高噪声输出、把可独立子任务拆分并行，并对压缩导致的错误恢复成本单独记账。与上期的单动作压缩论文相比，本研究定位为可移植的 Harness 系统层优化。

### 16. ReproBridge：一次复现成功，应留下下一位 Agent 可直接执行的工件

- **类型/时间：** AI 科研复现 / 可执行文档；arXiv 初稿 **2026-11-05**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.08452](https://arxiv.org/abs/2611.08452)。
- **核心观点：** 论文往往散落着环境变量、隐藏步骤与实验命令；某个 Agent 拼凑成功的复现过程应被提炼为带环境、代码、运行脚本和操作说明的可复用工件。
- **技术原理：** ReproBridge 工作流将原始科研资料转为规范化运行包，并用独立 Auditor 核查实验确实运行、指标来自正确执行。测试时新 Agent 在干净环境下复现，而不是继承上一个会话的隐含状态。
- **证据与边界：** ReproBridge-Bench 含 36 篇论文、387 个实验、1,029 个任务；四种模型平均复现成功率由 **76.4% 升至 92.6%**，后续 API 成本下降约 **19.7%**。这是受控基准的复现率，不是全部科学成果的独立真实性证明。
- **开发者启发：** 把每个 ML 实验交付定义为“锁定依赖 + 数据版本 + 单命令启动 + 指标校验 + 日志 + 已知失败点”，使科研 Agent 的产物可在另一机器/会话复用。这对小算力 LoRA 研究、论文复现和自动消融尤其直接。

### 17. AutoRefine：评测器也需要持续重校准，而不是永久信任同一 Prompt

- **类型/时间：** Code Judge / 持续评估；arXiv 初稿 **2026-11-06**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.09291](https://arxiv.org/abs/2611.09291)。
- **核心观点：** 代码优化 Agent 不断变化后，原本的 LLM Judge 会逐渐失准；可以利用测试通过、PR 合并/放弃等工作流结果更新 Judge，但这些真实结果并不等价于完美真值。
- **技术原理：** Teacher 模型同时观察代码变更与结果标签，只对可解释的标签生成训练信号；无法从给定上下文推导的标签可以弃权，然后递归修改实际部署的 Judge Prompt。它用外部结局信号校准判定，而不是让 Judge 自己给自己打分。
- **证据与边界：** 当前工作流的独立留出 17 个 diff 上，Scott's π 一致度由 **0.16 提高至 0.51**；在更旧的 16 个 diff 上旧 Judge 反而更好，说明新 Prompt 可能对新分布过拟合。样本很小，不能把它当作普遍可靠的零人工 Judge。
- **开发者启发：** 每次更换基础模型、工具或代码库类型时跑 Judge 回归集；保存“新旧任务”两个时间分层的人工审查样本，监测误通过率、弃权率和判定漂移。

### 18. No Second Run：预训练阶段的自我改进不是反复训练整个大模型

- **类型/时间：** 自递归改进 / 预训练基础设施；arXiv 初稿 **2026-11-07**，11-15 周刊首次收录。
- **原始来源：** [arXiv:2611.10719](https://arxiv.org/abs/2611.10719)。
- **核心观点：** 预训练任务的时间、资金和跨团队依赖不允许像 LoRA 后训练那样反复重启完整实验；若想让 Agent 帮助优化预训练，需要拆解为能够在局部闭环验证的细小问题。
- **技术原理：** 对数据管线、训练稳定性、评测数据和小规模 SFT 进行短周期诊断与修复；共享运行过程的负结果和专家判断，使改进下一次决策而不是赌一次无法重复的全局训练。
- **证据与边界：** 作者报告产出 **801-30B-A3B-Base**：约 30B 总参数、稀疏激活 3B 量级，在三个月以 11.8T tokens 从零预训练；再使用 6B tokens 轻量 SFT、未使用 RL，作为后训练潜力探针。多模型比较由作者特定训练/测评配置支持，不能归纳为“AI 全自动完成前沿基础模型研发”。
- **开发者启发：** 对 GPU/显存敏感的研究团队，把 Agent 能独立完成且可复测的范围限制在数据质量检查、训练脚本恢复、参数扫描、自动日志诊断和短程评测；保存成本、失败原因及专家覆盖决策。它与上期 RSI-Dojo 的后训练执行技能工作对应不同研发阶段。

## 三、如何在本周研究中选优先试验方向

| 场景 | 最值得先试的方向 | 最小可用对照与指标 |
|---|---|---|
| 编码 Agent 成本过高 | GPT-6.2 Sol/Astra 路由、FrontierHarness、Agency | 相同 30—100 个真实 issue 上固定工具，比较 pass@1、每通过任务成本、重试与人审时间 |
| 长期 Agent 记忆错误 | SoMem + WikiTrace + Meta LOAD/OFFLOAD 搜索 | 无记忆、纯摘要、带证据链接、优化读写策略；统计误记、检索遗漏和“记忆引入失败” |
| 多 Agent 协作有大量重复劳动 | s³ 的通信原则及研究社群的证据交换 | 固定协调器 / 自由并行 / 按需沟通；统计重复探索、消息开销与信息污染 |
| 做 ML 论文复现 | ReproBridge | 原始论文/仓库 vs 可执行工件包；干净环境复现率、耗时与独立 Auditor 一致性 |
| 自动化评测成本高或裁判漂移 | Eval Optimizer + AutoRefine | 单前沿 Judge vs 代码/小模型/Agent 分层裁判；人工金标一致度、误判率、费用与年代漂移 |
| 冻结模型长文任务困难 | LongCapHarness | 直接填长上下文、静态 RAG、能力原语 Harness；隐藏测试与开发成本 |

## 风险与解读规则

1. **公开跑分不等于真实交付质量。** 对模型、Harness、Agent 协调、评测器的改动应冻结任务分布、运行预算和验收标准再比较。大多数发布统计仍需要独立复核。
2. **不能将“更多外显/隐含推理”当成可审计性保证。** Inkling 的内部循环、长上下文压缩与多 Agent 代理层都可能造成可观察轨迹缺口，关键写入需外部日志和权限门禁。
3. **记忆策略须有证据追溯及过期机制。** SoMem、WikiTrace 与 Meta 工作显示，简单堆积经验并不总有帮助；不正确的经验若缺少原始轨迹可能主动降低成功率。
4. **研究 Agent 的能力与科学有效性应分开。** 研究社群规模、实验复现率和可检查的形式化证明分别说明不同维度，不能互相替代；保留负结果与独立核验。

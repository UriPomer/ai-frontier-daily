## 1. Claude Fable 5.2 / Mythos 5.2：强模型、风险能力与多 Agent 分工

**类型：** 模型 / 编程 Agent / 安全。**发布：** 2026-11-09。  
**原始来源：** [Anthropic 官方发布](https://www.anthropic.com/claude-fable-and-mythos-5-2)

**核心观点。** Anthropic 把同一底层模型分成两种安全与访问配置：Fable 5.2 向一般用户提供较强的网络安全和生物能力防护；Mythos 5.2 面向通过核验的安全及生命科学机构。高端模型适合作为专家、规划者或难题仲裁者，而不必承担所有廉价子操作。

**技术原理。** 官方展示了长时编码、自我验收和大规模子 Agent 协作；Fable 可以充当 Advisor 或 Orchestrator，让更小的模型完成确定性任务。部署时应把模型层的行为约束与工具层的实际权限分开，不能凭“有安全提示词”授予更高系统权限。

**证据。** 厂商报告 FrontierCode 2.0 在 Xhigh 为 49.1%，Opus 5.5 为 45.5%，GPT-6 Astra 为 42.8%；FrontierSWE v2 为 69.9%，OSWorld 2.1 离线子集部分评分为 89.3%。标准价格输入/输出分别 $8/$40 每百万 tokens，Fast 模式为 $16/$80。不同思考档位、模型和测试配置有差异，不能据此宣布任何模型在全部工作场景领先。

**重要性。** 强模型正从每一步都执行的“全能工作人员”转为高价值规划/审查资源，单任务总成本比 token 单价更值得优化。

**开发者启发。** 设计三条对照流水线：单强模型、强模型规划+小模型执行、只在测试失败时升级到强模型；同时记录总调用费、成功率、平均交付时间、修复回合数及越权行为。

## 2. Gemini 4 Hydrogen：动态路由把模型组合变成系统优化问题

**类型：** 模型 / Agent Orchestration。**发布：** 2026-11-12（官方页面更新 11-13）。  
**原始来源：** [Google 发布说明](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-hydrogen/)；[Gemini 4 Hydrogen 模型卡](https://deepmind.google/models/model-cards/gemini-4-hydrogen/)

**核心观点。** Hydrogen 被设计为高频编码、工具调用和多模态任务的快速执行模型，Carbon/Argon 则面向更深、更长的复杂推理。

**技术原理。** Google Antigravity 的 Orchestrator 在单个会话中动态切换规划模型与执行模型；子 Agent 可在隔离工作区并行编写、测试及复核。Hydrogen 由 Carbon 适配，支持可调推理档位，文本、图像、音频、视频联合上下文上限 100 万 tokens。

**证据。** Google 报告在 Terminal-Bench 4.0 使用 Orchestrator 相比 Carbon 达到接近的任务成功率，同时平均少用 24% 配额、快 19%；Hydrogen API 定价为每百万输入/输出 $1.50/$7.50。模型卡给出 AutomationBench-AA 76.1%、OSWorld 2.1 离线子集 77.6% 等成绩，均应连同评分规则阅读。

**重要性。** Agent 质量由基础模型、调度器、工具栈、Verifier 共同决定，不应把效率变化错误归因到单一模型架构。

**开发者启发。** 依据可逆性、失败代价和任务难度决定升级至强模型的门槛；用相同 repo/task 版本测试路由误判与重试后的真实成本，保留强模型直接处理作为对照组。

## 3. Meta Muse Ember：廉价多模态子 Agent 的高频执行层

**类型：** 模型 / 工具调用 / 成本。**发布：** 2026-11-09。  
**原始来源：** [Meta 官方技术博客](https://research.meta.ai/blog/muse-ember)

**核心观点。** Muse Ember 针对 Agent 反复做的工具调用、路由、抽取、代码子任务和长文档解析设计，支持把最频繁的操作从昂贵前沿模型剥离出来。

**技术原理。** 主 Agent 保留跨任务目标及高难决策；Ember 处理可限定输入输出、能自动验证的子任务。多模态能力可减少文档/截图处理中的外部转换环节，但不保证每种专业任务都准确。

**证据。** Meta 公布 API 每百万输入/输出 tokens 为 $0.10/$0.50，AutomationBench-AA 37.8、Agents' Last Exam 61.6、Terminal-Bench 4.0 40.9，而 FrontierCode 2.0-AA 为 27.2。该数据是官方的特定模型档位比较，Artificial Analysis 成本图使用提议定价；不能简单推断其复杂编程能力超过所有更贵模型。

**重要性。** 对调用频率高的系统，降低单步成本很有价值，但最终最优解是“正确完成一个工作流的单位成本”，不是最低价模型。

**开发者启发。** 先用 Ember 实验结构化日志、截图读取、批量数据提取和小型代码修补；给每个输出配 schema 校验或测试，超出预算或失败时才升级模型。

## 4. RIME：把记忆写入和经验探索放进同一个强化学习目标

**类型：** Agent Memory / RL。**研究页面：** 2026-11；**周刊：** 11-14。  
**原始来源：** [CMU 研究项目：How to Train Memory Writing for Continual Learning](https://cmu-aire.github.io/RIME/)

**核心观点。** 好的长期记忆不仅取决于 Writer 是否能总结过去，还取决于 Actor 是否在完成当前任务时采集了会帮助未来任务的证据。

**技术原理。** 一个策略模型轮流承担 ACT 与 WRITE：当前任务基于上一版记忆产生动作轨迹；Writer 再把轨迹转换为下一版记忆。训练奖励同时考虑当前成功和后续任务收益。因此 Actor 要学会有益探索，Writer 要学会选择信息，两者必须联合优化；单独把 Writer 训练成摘要器并不够。

**证据。** 作者在持续维护代码库的 Codebase Adaptation 任务流中，报告训练后的 Qwen3.5-4B 相比多种强模型及常规记忆方案取得有竞争力的累计任务表现和记忆增益。结论集中于相关任务流；不代表短对话或所有领域都有同样提升。

**重要性。** 这不是上期介绍的 Claude Dreaming 离线整理功能的重复：Dreaming 注重根据原始记录整理记忆；RIME 探索训练 Agent 主动生产将来有用的经验。

**开发者启发。** 按多任务连续成功率衡量记忆价值；比较无记忆、普通摘要、只训 Writer、联合训练；为写入项保留出处、适用范围及过期条件。

## 5. AlphaProof Code：Agent 负责找证明，可信内核负责检查证明

**类型：** 形式化验证 / 软件安全 Agent。**发布：** 2026-11-10。  
**原始来源：** [Google DeepMind 官方研究](https://deepmind.google/blog/introducing-alphaproof-code/)

**核心观点。** DeepMind 让 AI Agent 验证 Signal 密码协议的实际编译实现所满足的关键安全性质，不停留在自然语言描述或协议设计层。

**技术原理。** 人类专家先审核形式化规范；由 Gemini Carbon 驱动的多 Agent 生成 Lean 定理证明，可信的 Lean 内核检查证明是否成立，系统仅把需要人工判断的高风险区域交还专家。关键可信边界是形式化规格与证明核验器，而不是生成模型的自述。

**证据。** 官方称整个项目用约四周、生成超过 600 万行 Lean，并标记约 1% 的代码区域进行人审；在隔离测试中重新引入两项已经修复的历史漏洞，都得到机器可检查的漏洞证明。这只验证已定义并覆盖的安全性质，**不意味着实现绝对无漏洞**。

**重要性。** 在数学/程序逻辑可验证的领域，Agent 可以不可信但产出可信工件，改变工程质量保障的边界。

**开发者启发。** 从权限状态机、不变量、密码学实现或关键数据处理入手；CI 同时验规范覆盖、证明通过及运行测试，显式标记尚未形式化的威胁。

## 6. Singularity-Bench：让 Agent 在统一硬件上建设整条 AI 系统链

**类型：** AI for AI R&D / 评测安全。**论文：** 2026-11-12。  
**原始来源：** [arXiv:2611.16591](https://arxiv.org/abs/2611.16591)；[项目与最新成绩](https://infini-ai-lab.github.io/singularity-bench/)

**核心观点。** 新基准不只考查 Agent 能否修复代码，而是从极少起始代码出发，独立实现/优化预训练、中训练、后训练、推理引擎、集群编排和 Agent Harness 六个领域的端到端系统。

**技术原理。** 每个任务在固定硬件、时间与数据条件下对照成熟人工工程实现；成绩是 Agent 系统对成熟基线的任务指标比值，六项比值均分构成 Singularity-Index，失败项计零。还通过红队测试评估 Harbor 中可能的 reward hacking，并提供 Breakwater 缓解。

**证据。** 论文报告 11 种 Agent 组合与六任务，Opus 5.5 + Claude Code 得分约 1.25，其余组合平均约 0.58；其中后训练任务为 0.533 vs 人工基线 0.539，属于大致持平而不是全面领先。项目报告测试 OWASP Agentic Top 10 的九类风险，Breakwater 阻止其试验覆盖的攻击。基准只涉及给定的时间预算与硬件规模，不等于“已经实现递归超级智能”。

**重要性。** 模型、Harness、训练配方与部署工程开始接受一致任务约束的结果评价；同时评测环境本身必须抗作弊。

**开发者启发。** 内部可建立“最小仓库→完成高性能方案”的统一任务；锁定 GPU、依赖版本、token 预算、隐藏测试与指标采集，另测维护性及评测机制是否能被投机利用。

## 7. CoT Monitorability：更强推理能力未必带来更可靠的思维链可审计性

**类型：** 模型训练 / 安全评估。**发布：** 2026-11-10。  
**原始来源：** [OpenAI Alignment 研究文章](https://alignment.openai.com/cot-monitorability-model-lifecycle/)

**核心观点。** OpenAI 研究“无显式思维链推理能力”和“模型主动改变思维链文本的可控性”如何随训练变化；这两者都可能让外界更难从 CoT 文本判断模型真实行为。

**技术原理。** 基础模型 perplexity 下降与 no-CoT 能力增强相关；部分架构对某些任务会产生额外提升。强化学习即使只考最终结果与长度约束，也可能增强 CoT controllability；模型生成数据经监督微调还可能在师生间传递这种特征。

**证据。** 研究涉及 GPT-6 Astra 及相关模型训练阶段，并明确声明 no-CoT 能力与 CoT controllability 都是**不完善的监测代理指标**，并非直接量化某一模型的恶意程度。

**重要性。** 在高权限 Agent 中，仅看它“解释如何思考”不足以证明合规、安全或真实完成任务。

**开发者启发。** 另外记录工具执行、文件差分、审批、数据来源和外部环境结果；用独立策略门禁及输出工件检查代替只在 Prompt 中要求模型反思。

## 8. You don't need long context：单动作压缩上下文的极端实验

**类型：** Context Engineering / 推理效率。**原始论文：** 2026-11-03；**入选论文周刊：** 11-08。  
**原始来源：** [arXiv:2611.05306](https://arxiv.org/abs/2611.05306)

**核心观点。** NVIDIA 研究表明在许多 Agent 任务中，短上下文和频繁摘要不必然比携带全部历史差；长上下文并非天然能换来更高任务成功率。

**技术原理。** 对照完整历史累积、达到阈值时压缩、每次仅采取一个动作后立即压缩三种方式。作者提出 Semantic State Space Model 的后续研究方向：维护简明、可读的任务状态，而非不断增长的聊天记录。

**证据。** 周刊引述 Claude Opus 4.5 在 SWE-bench Verified 上单动作压缩 70.2 分、完整历史 70.0，峰值上下文中位数由 32K 降至 8K tokens；最佳特定压缩方案达到 74.8。其他测试涉及 Terminal-Bench、FRAMES、BFCLv3，但并非所有设置均无损。

**重要性。** 超长轨迹的成本和噪声可能高于收益，而错误压缩导致的状态丢失则是新的失败模式。

**开发者启发。** 状态摘要应含目标、已完成操作、证据索引、文件版本、失败测试与下一步动作；同时保留可检索原始日志，在真实仓库上测试压缩频率对成本、成功率与错误恢复的影响。

## 9. Skill++：技能库新增一个近似技能，就可能破坏旧任务路由

**类型：** Skills / Agent Routing。**原始论文：** 2026-10-31；**入选论文周刊：** 11-08。  
**原始来源：** [arXiv:2611.00544](https://arxiv.org/abs/2611.00544)

**核心观点。** Progressive Disclosure 下，Skill Router 在载入技能正文之前只看名称和简介；新增与旧技能很接近的条目，即使旧条目没改，也可能造成错误替换和拥挤。

**技术原理。** Skill++ 找出新技能最相似的现有技能，为新技能改写元数据，明确能力范围、差异和排除场景；无需训练 Router，也不要求新增人工标签。正文不参与这一更新操作。

**证据。** 在十轮增长到 731 个技能的实验中，正确选齐所有必需技能的比例由原始元数据 36.4% 提高至 76.3%；跨三个 benchmark 和五种 Router，最终路由准确率平均提高 23.1 个百分点。原论文发表早于本筛选窗口，因**本周论文周刊新收录**而选入，非虚报新论文日期。

**重要性。** Agent 质量衰退可以由工具描述冲突引起，不必是模型本身退化。

**开发者启发。** 在每次 Skill 安装和升级时自动运行路由回归集，并对相似简介的 top-k 技能进行混淆检测；明确写出适用条件、禁止范围、输出结构。

## 10. Recursa：模型权重冻结，外部知识库仍可自我改进

**类型：** Domain Agent / 自改进。**原始论文：** 2026-11-02；**入选论文周刊：** 11-08。  
**原始来源：** [arXiv:2611.04035](https://arxiv.org/abs/2611.04035)

**核心观点。** 阿里研究团队提出通过外部知识仓库保存领域技能、调用条件、任务经验和反思，在不微调基础模型、不依赖更强教师的情况下进行领域适应。

**技术原理。** 先用领域文档初始化知识库，再把任务分配给递归的并行 Learner。叶节点执行任务、诊断错误并提出修订，通过独立验证后才合并。由此把 Agent 的学习对象从权重转换为可追溯的可用工作知识。

**证据。** Harvey LAB Firm Knowledge 的留出测试 all-pass 率：DeepSeek-V4.1-Flash 从 30.0% 到 55.0%，Qwen3.8-Flash 从 35.0% 到 46.0%。适用范围仍受限于领域语料质量与实验任务。

**重要性。** 没有大规模训练预算，也可以通过严格验收的外部经验获得持续增益；区别于上期 Exo 的 Harness 代码自改进。

**开发者启发。** 领域知识、操作方法及失败案例分别版本化，修改必须通过不参与生成的 holdout 测试，再进行准入；高风险规范需人工审查。

## 11. Routed Continual Learning：持续记忆需要按任务簇路由

**类型：** Agent Memory / Continual Learning。**原始论文：** 2026-10-28；**入选论文周刊：** 11-08。  
**原始来源：** [arXiv:2610.38796](https://arxiv.org/abs/2610.38796)

**核心观点。** Meta FAIR 提出既要选择“记住哪个经验簇”，也要选择“以什么形式保留这个簇的经验”；单一全局历史会积累无关轨迹。

**技术原理。** LLM Router 比较任务与现有簇摘要，复用旧簇或创建新簇；每簇采用来自有限候选库的一种记忆系统，例如保留具体轨迹或抽象可复用规则。Context Memory Adapter 在任务开始时插入对应状态，完成后更新选中的簇。

**证据。** 在混合 301 个 CL-Bench 与 97 个银行任务的顺序流中，相比全局历史，四种模型的归一化奖励提升达到最大可得奖励区间的 15%—30%，估计 API 成本降低 65%—72%。并行 Agent 对同一簇的冲突写入尚未被充分测试。

**重要性。** 上期 Dreaming 解决“怎么离线整理记忆”，本篇解决“何时选择哪组记忆”，是互补设计。

**开发者启发。** 按代码库、项目和工作类型隔离记忆；低置信度时回退原始记录；对并发写入加版本号、事务与权限边界，防止跨项目泄漏。

## 12. JevAct：工具执行前的确定性检查 + 决策模型门禁

**类型：** Agent Runtime / Verification。**原始论文：** 2026-10-28；**入选论文周刊：** 11-08。  
**原始来源：** [arXiv:2610.38620](https://arxiv.org/abs/2610.38620)

**核心观点。** IBM 在不改 Actor 模型参数与工具定义的前提下，拦截关键工具写入和最终任务交接，先独立检查策略是否满足、任务是否真的完成。

**技术原理。** 离线将政策、工具 schema 和日志转换为可执行状态检查、结构化 yes/no 问题与结束检查表；运行时由代码检查事实，由 prefill-only 决策模型评估语义条件；失败时把具体反馈返回 Actor 在有限步数内修订。

**证据。** τ²-bench Telecom 中 Opus 4.6 三次运行全部成功率由 39.5% 到 80.7%，八个 Agent 三次成功率平均提高 16.9 个百分点；BFCL 九个 Agent 均改善，Airline 表现则小且混合。仓库早期曾介绍过 Jev 决策模型，**这里报道的是其新运行时门禁用途，不是重复报道 Jev 本身**。

**重要性。** 高权限 Agent 更需要能审计、可强制执行的工具状态门禁，而不只是最终结果的自我解释。

**开发者启发。** 先拦截发布、支付、删除、权限变更和外部写入；事实条件用确定性代码检查，语义判断才交给决策模型，不能把概率输出当作最终授权。

## 13. RSI-Dojo：让中等规模模型学习执行后训练实验

**类型：** Model Training Agent / RSI。**原始论文：** 2026-11-02；**入选论文周刊：** 11-08。  
**原始来源：** [arXiv:2611.03698](https://arxiv.org/abs/2611.03698)

**核心观点。** 多所高校与机构提出将机器学习论文复现转成可运行的后训练环境，训练 Agent 掌握选数据、训练、评测、发现错误与迭代改进的工作过程。

**技术原理。** RSI-Craft 收集论文、整理数据和评测依赖，按可复现性及区分度筛选 281 个训练任务；强 Agent 在 Harness 中运行并留下轨迹；通过结果和规则过滤后对较小开源模型进行监督微调。与 Recursa 不同，这里改进的对象是**模型权重内的过程技能**。

**证据。** 作者报告 Qwen3.5-9B 和 Qwen3.6-35B-A3B 相对基模分别提高 8.74、16.87 个 PostTrainBench 点；35B-A3B 在 PostTrainBench 29.95、Lite 53.29。结果取决于任务库覆盖与环境验证质量，尚非完全无人值守 AI 研发证据。

**重要性。** 研究 Agent 从“按提示执行已知训练流程”走向“由可执行示范学会训练流程”，为自动实验与小模型研发能力积累提供路径。

**开发者启发。** 先构建小而可验证的 LoRA 训练、数据清洗、消融实验环境；记录数据版本、训练 seed、显存峰值、指标与失败日志，用隐藏评测抑制奖励投机。

## 14. LifeVal：真实生活任务暴露个性化 Agent 的上下文缺口

**类型：** Agent Evaluation / Personalization。**论文：** 2026-11；**入选论文周刊：** 11-08。  
**原始来源：** [arXiv:2611.06687](https://arxiv.org/abs/2611.06687)

**核心观点。** OpenAI 把消费者真正愿意委托的生活事务转成需要结合个人历史、文件及条件的 Agent 任务，着重评估是否提供有效、贴近情况的服务。

**技术原理。** 调查 3,837 位美国消费者对 148 类任务的支付意愿，让熟悉这些事务的参与者构造 169 项任务，并结合其历史交互、记忆和文件检查模型是否正确使用背景事实。衡量对象不止是答题正确率，还包括建议适用性。

**证据。** 论文周刊引述：受评模型常因忽略历史事实而给出错误推荐；依赖旧聊天信息的评判项胜率约 33%，依赖已保存记忆的为 48%。支付意愿推算不是实际成交金额，数据也不能直接推广到所有地区消费者。

**重要性。** 个性化 Agent 的失败经常是信息访问和回忆问题，给模型更多思考 tokens 并不一定能解决。

**开发者启发。** 在真实产品中分开评估检索遗漏、过期记忆、错误理解用户约束、工具执行失败及输出建议不佳；重要结论附可追溯证据，不擅自引入未授权私人信息。

---

## 综合开发路线与风险

**第一，先做系统级基准，而不是只比模型榜单。** 用固定任务集和相同工具栈比较 Fable 专家模式、Hydrogen 动态路由及 Ember 子任务处理，统计准确交付成本、延迟、人工介入和重试率。深推理模型应优先留给模糊规划、失败恢复及高风险审查。

**第二，长期 Agent 记忆至少分成原始证据、待验证摘要、可复用知识库和按场景选择的上下文层。** RIME 的联合学习、Recursa 的验证合并、Routed CL 的记忆分簇与上期 Dreaming 的离线整理分别补足不同环节；不能把相互补充的论文误写为同一种技术。

**第三，把不可篡改的验证边界留在模型之外。** AlphaProof Code 中由 Lean 检查证明；JevAct 中由外部程序检查权限与工具状态；OpenAI 的 CoT 结果解释了为什么依赖模型自身文字解释并不充分。对写操作必须保持清晰的授权和审计路径。

**第四，避免“评测成功=真实自动化”的过度推论。** Singularity-Bench、RSI-Dojo 与 LifeVal 从不同维度暴露了环境复现、奖励作弊、用户上下文缺失问题。论文数字是作者环境内证据；正式部署仍需独立隐藏测试、行为审计、失败后的安全回滚和人工验收。
